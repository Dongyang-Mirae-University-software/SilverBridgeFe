## 4. 보안 (PHASE 2)

### 라우트 × 역할

`middleware`는 없다. 세 화면 그룹 레이아웃이 클라이언트 `RoleRouteGuard`(역할 출처 = `/api/user/me` 응답)로 감싼다. 확인 전에는 안내 화면만 그리고 자식 화면은 렌더하지 않는다. 가드 밖에 놓인 보호 페이지는 없다. 데이터 인가는 BE가 한다.

| 라우트 | 비로그인 | 피보호자 | 보호자 | 관리자 |
|---|---|---|---|---|
| `/` | `/login` | `/ward` | `/guardian` | `/admin` |
| `/login` | 열림 | 홈으로 | 홈으로 | 홈으로 |
| `/signup`·`/find-email`·`/find-password`·`/oauth` | 열림 | 열림 | 열림 | 열림 |
| `/ward/*` | `/login` | 허용 | 보호자 홈으로 | 관리자 홈으로 |
| `/guardian/*` | `/login` | 피보호자 홈으로 | 허용 | 관리자 홈으로 |
| `/guardian/wards/register` | `/login?returnTo=` | 안내문(이동 없음) | 허용 | 안내문 |
| `/admin/*` | `/login` | 피보호자 홈으로 | 보호자 홈으로 | 허용 |

### BFF·프록시 허용 목록

| 경로 | 넘기는 범위 | 판정 |
|---|---|---|
| `/api/[...path]` | BE `/api/**` 전체(인가는 BE). gosky에서 `/api/%2e%2e/...`는 404, `..%2F`는 400 - `/api` 밖으로 못 나간다 | 정상 |
| `/api/streams/[...path]` | POST + 송출 3경로(세션 생성·`frame`·`stop`)만, 피보호자 역할 검증 후. AI 임의 경로는 닫혀 있다 | 정상 |
| `/api/reservation/[...path]` | (메서드, 경로) 5개, 쿼리·본문 필드를 다시 조립, 쓰기는 ACTIVE 연결 보호자만 | 정상 |
| `/api/oauth/kakao/authorize` | 카카오 인가 주소로만 이동, `returnTo`는 같은 출처 경로만 | S-5 참고 |

챗은 전용 프록시 없이 BE 중계(`/api/{ward,guardian}/chat/**`)만 쓴다. 챗·AI 임의 경로는 되살아나지 않았다.

### 이슈

**S-1 🟠 access·refresh 토큰을 JS가 읽는 쿠키에 둔다**
- 위치: `src/lib/auth/tokenStore.ts:24-27`(쿠키 쓰기), `:63-65`, `src/lib/api/apiClient.ts:160-162`(본문 `refreshToken`으로 갱신)
- 내용: `careai_access_token`·`careai_refresh_token`을 `document.cookie`로 쓴다. HttpOnly·Secure가 없고 7일 유지다. BE는 2026-10-06에 refresh를 HttpOnly 쿠키 `careai_rt`로 내리기 시작했지만 FE는 본문 값을 계속 저장·전송한다(BE 전환 플래그 `body-compat`에 의존).
- 재현: 로그인 뒤 콘솔에서 `document.cookie` → 두 토큰이 보인다. 스크립트가 한 번 실행되면 7일짜리 refresh 토큰까지 가져갈 수 있다.
- 완화 요인: HTML 삽입 지점 0건, 외부 스크립트는 카카오·Firebase 고정 버전뿐.
- 수정안: refresh는 저장하지 않고 `careai_rt` 쿠키로만 갱신한다. access는 메모리에 두고 새로고침 때 갱신으로 복원한다. access 쿠키를 읽는 서버 쪽(`src/app/page.tsx`·`login/page.tsx`·streams·reservation BFF·서비스 워커)의 대체가 함께 필요해 설계가 먼저다.

**S-2 🟠 프록시가 요청 쿠키를 지워 BE의 HttpOnly refresh 쿠키가 전달되지 않는다**
- 위치: `src/app/api/[...path]/route.ts:7`(`cookie`를 제거 목록에 둠), `:50`
- 내용: 브라우저는 `careai_rt`를 `/api/auth/*` 요청에 실어 보내지만 프록시가 지운다. 지금은 본문 값으로 갱신돼 드러나지 않는다. BE가 `body-compat`을 끄면 갱신 응답의 `refreshToken`이 null이 되어 `apiClient.ts:167`에서 세션 거절로 처리된다 - **전 사용자가 access 만료 시점에 로그아웃된다.**
- 수정안: `/auth/*` 경로에 한해 `careai_rt` 쿠키만 골라 BE로 넘긴다. S-1과 한 묶음으로 진행하고, **BE는 FE 전환 배포 전에 `AUTH_REFRESH_COOKIE_BODY_COMPAT`을 끄면 안 된다.**

**S-3 🟡 WebSocket 로그가 운영 빌드에서도 알림 내용을 콘솔에 찍는다**
- 위치: `src/lib/realtime/connectionSocket.ts:223`(STOMP 프레임 전체), `:229`·`:235`(userId), `:239`(알림 페이로드 전체)
- 내용: 조건 없이 출력한다. 페이로드에는 피보호자 이름·위치·약 이름·감지 종류가 들어간다. 토큰은 문자열 치환으로만 가린다. `removeConsole` 설정도 없다.
- 수정안: 개발 환경에서만 출력하거나, 종류(type)만 남긴다.

**S-4 🟡 응답 보안 헤더가 없다**
- 위치: `next.config.ts`(`headers()` 없음). gosky dev `/login` 응답에서 CSP·`X-Frame-Options`·HSTS·`X-Content-Type-Options`·`Referrer-Policy`가 모두 없는 것을 확인했다.
- 내용: 다른 사이트가 화면을 iframe에 넣을 수 있다(SOS·탈퇴 버튼 클릭 유도).
- 수정안: `frame-ancestors 'self'`·`nosniff`·`Referrer-Policy`부터 넣는다. 전체 CSP는 카카오·Firebase 출처를 정리한 뒤 단계적으로.

**S-5 🟡 카카오 로그인 `state`가 난수가 아니다**

### 6-2. 작업 중 새로 찾은 문제

**F-7 🔴 카카오 신규 가입이 항상 400으로 실패했다 - 반영(#233)**
- BE는 가입 완료(`POST /api/auth/signup/kakao`)에 `pendingToken`을 필수로 받는데(2026-10-02, `@NotBlank`) FE 코드에는 `pendingToken`이 한 군데도 없었다. 카카오 로그인 응답의 값을 받지도, 가입 요청에 싣지도 않았다.
- 수정: 콜백이 `pendingToken`을 가입 화면으로 넘기고 가입 요청에 싣는다. 값이 없으면 가입 화면으로 보내지 않고 오류를 보인다.
- 한계: **카카오 실계정으로 가입을 끝까지 해 보지는 못했다**(새 카카오 계정 필요). 브라우저 테스트 5건과 authorize 응답으로만 확인했다.

**가입 화면 반복 렌더(수정 중 발견, 배포 전 수정)**: 가입 정보를 effect에서 읽어 상태에 넣을 때 매번 새 객체를 넣으면 다시 그려진다. 브라우저 테스트가 멈춰서 찾았고, 이미 읽었으면 그대로 두게 했다.
