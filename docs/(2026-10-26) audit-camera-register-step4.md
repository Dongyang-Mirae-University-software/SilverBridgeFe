## 4단계 버튼 상태 표 (마법사 4단계, 등록 중이 아닐 때)

| status | isMediaStarting | isMediaTried | 보이는 버튼 |
|---|---|---|---|
| off | false | false (첫 화면, effect 실행 전) | 비활성 "화면을 고르는 중..." / "카메라를 켜는 중..." |
| off | true | true (선택·권한 창) | 위와 같음 |
| off | false | true (취소·거부, 미리보기 중 멈춤) | "카메라 다시 켜기" |
| ready | - | - | "등록하고 촬영 시작"(등록 중이면 비활성 "촬영 시작하는 중...") |

- 4단계를 떠나면(이전·창 닫기·마법사 종료) `isMediaTried`가 초기화된다. 이전 → 다시 4단계에서도 켜는 중 → 등록 버튼 순서로 보인다(확인 테스트 c, `getUserMedia` 2회).
- 비활성 "~하는 중"에 갇히는 조합은 찾지 못했다. 켜기가 끝나면 `finally`에서 `isMediaStarting`이 풀리고, 시도한 뒤에 꺼지면 "다시 켜기"가 보인다.

## 이슈

### 🟡 M-1 켜는 중에 닫기·이전을 누르면 늦게 켜진 미디어가 정리되지 않는다 (원래 있던 결함, #148 무관)
- 경로: `handleClose`·`handleWizardBack`은 `status === 'ready'`일 때만 `handleStopMedia`를 부른다. 화면 선택·권한 창이 떠 있는 동안에는 `status`가 아직 `'off'`라서, 사용자가 나중에 선택을 끝내면 `openMedia`가 `ready`로 만들고 미리보기 루프를 시작한다.
- 재현(확인 테스트 a·b, 809a702에서도 같은 결과):
  - 창을 닫은 뒤 선택 → 트랙 `live`(숨은 창에서 화면 공유·카메라가 켜진 채 남음). 다시 열면 새 등록 초기화 effect가 `status !== 'off'`라 건너뛰어 1단계가 아니라 **4단계**가 보인다.
  - '이전' 뒤 선택 → 3단계에서 촬영 방식 버튼이 **잠긴다**(`disabled={status !== 'off'}`). 다시 '다음'을 누르면 그 스트림으로 등록할 수는 있다.
- 영향: 카메라·화면 캡처가 사용자가 모르게 켜져 있을 수 있다(화면 공유는 브라우저 표시줄로 알 수 있음). 등록·송출이 시작되지는 않는다.
- 수정 방향(제안): 켜기 시도마다 세대 번호를 ref로 두고, 4단계를 떠나거나 창을 닫으면 번호를 올린다. `openMedia`가 끝났을 때 번호가 바뀌어 있으면 받은 트랙을 멈추고 `status`를 `'off'`로 둔다. 확인 테스트 a·b를 그대로 회귀 테스트로 고정한다.

### 🟢 L-1 미리보기 중 브라우저 '공유 중지'를 누른 경우 (추정, 재현하지 않음)
- 4단계 미리보기(`ready`)에서 화면 공유를 끊어도 끊긴 화면을 감지하는 `handleStaleSource`는 송출 루프에서만 돈다. 그래서 '등록하고 촬영 시작'이 활성으로 남고, 등록 뒤 송출이 바로 멈춰 "카메라가 멈춰서…" 알림이 나올 것으로 보인다. #148 이전부터 같다.

- #148 테스트 5건은 켜는 중 문구 2종·취소 뒤 다시 켜기·상한 안내 위치·등록 성공 1회를 고정한다. 가짜 Worker 때문에 송출 루프는 돌지 않는다(이 PR 범위에서는 문제없음).

## 조치 (2026-10-27, `fix/camera-register-cancel-pending-media`)
- **M-1 해결**: `wantsPreviewRef`(열림 && 마법사 && 4단계)를 렌더마다 갱신하고, `handleStartMedia`가 켜기를 마쳤을 때 4단계가 아니거나 그 사이 촬영 방식이 바뀌었으면 받은 미디어를 `handleStopMedia`로 끄고 오류 문구를 띄우지 않는다. 지난번 켜기가 끝나기 전에 4단계로 돌아오면 자동 미리보기 effect가 `isMediaStarting`이 풀릴 때까지 기다렸다가, 결과가 버려졌으면 다시 켠다(그대로 쓸 수 있으면 그 결과로 미리보기를 보인다).
- **L-1 해결**: `openMedia`가 받은 영상 트랙에 `ended` 리스너를 단다. 송출 전(`liveSessionIdRef` 없음)이고 지금 쓰는 스트림이면 미리보기를 끄고 "미리보기가 끊겼어요. 다시 켜 주세요."를 보인다 → 4단계 버튼은 "카메라 다시 켜기". 송출 중에는 기존 송출 루프(`handleStaleSource`)가 그대로 맡는다.
- **L-2 해결**: 브라우저 테스트 7건 추가(창 닫기 뒤 늦은 선택 / 이전 뒤 늦은 선택 / 선택 대기 중 4단계 재진입 / 이전 → 재진입 / 미리보기 중 공유 중지 / 방 중복 409 회귀 / 기존 카메라 오류 위치). 고치기 전 코드에서는 M-1 2건·L-1 1건이 실패한다.
