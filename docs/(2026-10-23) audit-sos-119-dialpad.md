## A. 안전·보안 - PASS
| 항목 | 결과 |
|---|---|
| 발신 경로 | 키패드와 하위(`Icon`)에 `tel:`·`sms:`·`intent:`·`window.location`·`window.open`·`<a>`·`Link` 없음. 가드 테스트(소스 검사)+브라우저 테스트(이동·새 창·링크 없음)로 고정 |
| 실서버 | gosky에서 휴대폰 흉내(iPhone 13 크기·터치, Chrome)로 통화 버튼을 눌렀다 - 주소 변화·새 창·비HTTP 요청 0건, 안내 문구 표시, 닫기 정상 |
| 거짓 안내 | "전화 거는 중"·통화 시간 같은 연결된 듯한 표시 없음. 상단에 "실제로 신고 전화가 발신되지 않습니다", 버튼 이름에 "실제로 걸리지 않음" |
| SOS 전송 | 키패드 열기·닫기·Esc가 전송을 취소·중복시키지 않는다(전송은 `handleHeroPress` 한 번, `isSending`으로 막음). 단 M-1의 키보드 경로는 예외 |

실기기(iOS Safari·Android Chrome)는 직접 누르지 못했다. 위 실서버 확인은 데스크톱 Chrome의 휴대폰 흉내다. 코드에 다이얼러를 여는 경로 자체가 없어 결과가 달라질 여지는 없다고 본다.

## 이슈
🔴 Critical·🟠 High 없음.

### 🟡 M-1 포커스가 키패드 밖으로 빠지고, 닫으면 돌아오지 않는다
- 재현: 키패드를 연 뒤 Tab을 누르면 20번 중 2번 키패드 뒤에 가려진 [긴급 SOS] 버튼으로 간다. 닫으면 포커스가 `BODY`로 떨어진다.
- 영향: 키보드·스위치 사용자가 보이지 않는 SOS 버튼을 누를 수 있다. 전송이 끝난 뒤라면 SOS가 한 번 더 나가고 키패드가 하나 더 쌓인다(`aria-modal`만으로는 포커스를 막지 못한다).
- 수정 제안: 키패드에 포커스 가둠(첫·마지막 버튼 사이 순환) + 열기 전 포커스를 기억했다 닫을 때 되돌림. 테스트: Tab을 여러 번 눌러도 포커스가 대화상자 안에 있다 / 닫으면 SOS 버튼으로 돌아온다.

### 🟡 M-2 가로 화면에서 키가 36px로 작아지고 통화 버튼이 화면 밖으로 밀린다
- 원인: 키 크기 `min(80px, 22vw, 9.6dvh)`에서 높이 375px이면 9.6dvh = 36px. 세로 스크롤로 닿기는 한다.
- 수정 제안: 최소값을 둬 `max(48px, min(80px, 22vw, 9.6dvh))`처럼 터치 영역을 지키고, 키가 넘치면 스크롤로 받는다(지금도 overlay가 스크롤된다). 테스트: 812×375에서 키 지름 ≥ 48px.

### 🟡 M-3 (기존 결함) "보호자에게도 알렸어요"가 한 번도 나오지 않는다
- 원인: `openDialModal(guardianNotified?)`을 부르는 세 곳 모두 인자 없이 부른다(#98 이전과 같다). 기본 설정(`CALL_119_AND_NOTIFY`)은 응답 전에 키패드를 열기 때문에, 보호자에게 실제로 알려졌는지 키패드에서 알 수 없다(실패하면 오류 모달만 뜬다).
- 수정 제안: 키패드에 전송 상태(`보내는 중` → `보호자에게 알렸어요` / 실패는 기존 오류 모달)를 보여 준다. `openModal`은 열 때의 요소를 저장하므로, 상태를 작은 스토어나 콜백 구독으로 넘기거나 성공 시 키패드를 같은 상태로 다시 그린다. 문구는 성공 응답을 받은 뒤에만 띄운다(거짓 안내 금지).

### 🟡 M-4 (기존 동작·별도 결정 필요) 보호자가 없으면 SOS 이력이 남지 않는다
- 원인: `handleHeroPress`가 연결된 보호자가 없으면 SOS API를 부르지 않고 키패드만 연다(2026-10-07). BE 정책은 "알림이 실패해도 이력은 무조건 남는다"(SOS 동작 설정, 2026-07-23)이다.
- gosky 실화면에서 확인: 테스트 피보호자(보호자 연결 없음)는 SOS POST 0건.
- 결정 필요: 보호자가 없어도 SOS를 보내 이력만 남길지(BE는 알림 대상 0명으로 처리) - 키패드 작업 범위 밖이라 이번에 판정하지 않는다.

### 🟢 L-1 초록 통화 버튼의 흰 아이콘 대비 2.69:1
- 그래픽 요소 기준 3:1에 조금 못 미친다. 초록을 한 단계 어둡게(예: `#25964a`, 3.79:1) 하면 맞는다.

### 🟢 L-2 주석이 가드 테스트 파일을 잘못 가리킨다
- `Emergency119Dialpad.tsx:12`의 "(Emergency119Dialpad.browser.test.tsx 가드)" → 실제 가드는 `Emergency119Dialpad.guard.test.ts`.

### 🟢 L-3 가드 테스트는 문자열 검사
- 문자열을 조합하면 통과할 수 있다. 브라우저 테스트가 실제 동작(이동·새 창·링크 없음)을 보완해 수용한다.

### 🟢 L-4 상단 안내가 대화상자 설명으로 연결되지 않았다
- 화면 낭독기는 대화상자 이름만 읽고 "실제로 발신되지 않습니다"를 바로 읽지 않을 수 있다. `aria-describedby`로 안내 문구를 연결한다.

## 종합 판정
**PASS(조건부)** - 실제 발신 경로가 없고 SOS 흐름도 바뀌지 않았다. 키보드 포커스(M-1)와 가로 화면 크기(M-2)는 이번 변경에서 생긴 것이라 다음 수정에서 함께 고치길 권한다. M-3·M-4는 #98 이전부터 있던 동작이다.
