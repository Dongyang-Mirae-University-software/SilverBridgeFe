# AI 의료 챗봇 화면 기능 점검 (2026-10-30)

> 대상: PR #165(보호자·피보호자 Claude 디자인 반영) 뒤 챗봇 화면과 공용 코드(`ChatbotContent`·`ChatBubble`) 사용처. 기록: `docs/(2026-10-30) design-chatbot-claude-design.md`

## 점검 범위와 결과

| 단계 | 결과 |
|---|---|
| 사용처 | `ChatbotContent`·`ChatBubble`은 `/guardian/chatbot`·`/ward/chatbot` 두 페이지에서만 쓴다. 다른 화면 영향 없음 |
| 실서버(gosky dev) | **못 했다** - 시험 보호자 계정 로그인 401(1회, 잠금 방지로 재시도 안 함). 피보호자 계정은 원래 로그인 금지 상태. 대신 실제 Chrome 컴포넌트 테스트로 확인 |
| 접근성 | 버튼 이름 = 보이는 글자, 입력창 이름 `궁금한 점 입력`, 응답 중 `role="status"` 문제없음. 아래 3·4 수정 |
| 휴대폰 키보드 | 키보드가 열린 높이(375×420)에서 대화 영역이 피보호자 77px·보호자 135px - 아래 1·2 수정 |

## 발견과 조치

| # | 심각도 | 내용 | 조치 |
|---|---|---|---|
| 1 | 중간 | 피보호자 화면이 1024px 이하에서 빠른 질문 칸(약 200px)을 대화 아래에 두므로, 입력창을 누르면 대화가 두 줄 남짓만 보였다(#165에서 생김) | 입력창에 포커스가 있으면 빠른 질문 칸을 숨긴다(`.wardBody:has(.textarea:focus)`, 1024px 이하). 보호자 칩 줄도 760px 이하에서 같게. 375×420 대화 영역 피보호자 77→279px, 보호자 135→222px |
| 2 | 중간 | 보낸 뒤 항상 입력창으로 포커스를 옮겨, 빠른 질문·선택지를 눌러도 안드로이드 키보드가 올라왔다(원래 있던 동작). 1번과 겹치면 빠른 질문 칸까지 사라진다 | 입력창에서 보낸 경우(Enter·보내기)에만 포커스를 되돌린다(`send`의 `refocusComposer`) |
| 3 | 낮음 | 입력창 `outline: none` + 포커스 스타일 없음 - 키보드 사용자에게 포커스 위치가 안 보였다(원래 있던 문제) | 포커스 때 테두리 `--sb-brand`(두 역할) |
| 4 | 낮음 | 피보호자 빠른 질문 버튼 테두리 `--sb-brand-soft`는 흰 바탕 대비 약 1.4:1, 휴대폰에서는 아이콘 칸을 숨겨 테두리만 남는다 | 고대비 설정(`wardHighContrast`)에서만 `--sb-brand`. 기본 화면은 디자인 그대로 |

## 변경 파일

- `src/components/chatbot/ChatbotContent.tsx` - 2번
- `ChatbotContent.module.css` - 1·3·4번
- `ChatbotContent.browser.test.tsx` - 입력창 전송 뒤 포커스 복귀, 빠른 질문 전송 뒤 포커스 없음, 375px 입력 중 칩 줄·빠른 질문 칸 숨김(피보호자는 입력을 마치면 다시 보임) 3건 추가

## 남은 것

- 실서버 화면 확인(보호자 피보호자 전환·대리 상담 예약 흐름·상담 기록)은 시험 보호자 계정 비밀번호가 갱신되면 다시 한다
- 실제 휴대폰에서 키보드가 열릴 때의 모습(iOS `visualViewport`)은 기기로 확인해야 한다
