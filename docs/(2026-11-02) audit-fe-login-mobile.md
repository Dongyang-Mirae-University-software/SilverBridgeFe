## 이슈

### 🟡 M-1 320px 폭에서 로그인 유지·찾기 링크 단어가 글자 단위로 쪼개진다 (회귀)
- 현상: 320×568에서 "로그인 유\n지", "아이디 찾\n기", "비밀번호 찾\n기". PR 이전에는 480px 이하에서 이 줄을 두 줄(로그인 유지 / 찾기 링크)로 나눠 생기지 않았다.
- 원인: 767 이하에서 한 줄(`flex-direction: row`)로 바꾸고 줄바꿈 금지를 두지 않음. 카드 안 폭이 약 340px 미만이면 모자란다.
- 수정 제안: `.remember`·`.textButton`에 `white-space: nowrap`, 그리고 `@media (max-width: 340px)`에서 `.secondaryActions { flex-wrap: wrap; row-gap: 6px; }`(또는 PR 이전처럼 세로 배치). 테스트: 320 폭에서 각 링크 높이가 한 줄 높이인지.

### 🟡 M-2 safe-area 여백이 실제로는 0이다 (`viewport-fit=cover` 없음)
- 현상: viewport meta가 `width=device-width, initial-scale=1`뿐이라 `env(safe-area-inset-*)`가 모든 기기에서 0. 요청의 "웹앱·노치 기기는 safe-area를 위아래 여백에 더한다"가 효과 없다.
- 영향: `cover`가 아니면 브라우저가 내용을 안전 영역 안에만 그리므로 **노치·홈 막대에 가려지는 일은 없다**(위험 아님). 다만 웹앱(standalone)에서 상태 표시줄 배경 처리 등은 기기마다 다를 수 있다.
- 결정 필요: `viewport-fit=cover`는 앱 전체(root layout) 설정이라 모든 화면의 위아래 여백에 영향을 준다 - 켤지, 지금처럼 둘지(실기기 확인 후).

### 🟡 M-3 하단 안내 글자 대비가 더 낮아졌다 (기존 미달, 2.61 → 2.38)
- 원인: 767 이하 배경을 `--sb-brand-50`으로 바꿨는데 글자색(`#a89884`, 기존 값)은 그대로.
- 참고: "간편 로그인" 구분 글자 2.29는 흰 카드 위라 이번 변경과 무관(기존).
- 수정 제안: 하단 안내 글자색을 4.5:1 이상 되는 `--sb-*` 토큰으로(후보는 실측 후 결정). 학습 목적 안내는 읽혀야 하는 문구다.

### 🟢 L-1 '로그인 유지' 터치 영역이 로그인 버튼 위 가장자리 2px와 겹친다
- 375×667: 로그인 유지 `::after` 범위 365~417px, 로그인 버튼 위 415px. 버튼 왼쪽 위 2px 띠를 누르면 로그인 대신 로그인 유지가 바뀐다(버튼 가운데는 정상).
- 원인: 라벨 높이 18px에 위아래 15px를 더해 48px가 됐다(44px면 충분).
- 수정 제안: `.remember::after`만 `inset: -13px -6px`(44px). 테스트: 각 버튼의 네 모서리 안쪽 지점 `elementFromPoint`가 자기 자신인지.

### 🟢 L-2 오류 문구가 두 줄이면 375×667에서 몇 px 스크롤될 수 있다
- 1줄 오류 문구 때 여유 11px. 서버 오류 문구가 길어 두 줄이 되면 약 7px 넘칠 것으로 보인다(스크롤 허용 범위, 잘림 없음). 실제 서버 문구로는 확인하지 않음.

### 🟢 L-3 테스트 공백
- M-1·L-1·다른 인증 화면 머리 부분·오류 상태 높이를 고정하는 테스트가 없다. M-1·L-1을 고칠 때 함께 추가 권장.

## 사용자 실기기 확인 요청

1. 아이폰 사파리·안드로이드 크롬에서 `devdmu.gosky.kr/login`이 한 화면에 보이는지(사파리는 주소창·도구 막대만큼 높이가 줄어 SE는 조금 스크롤될 수 있음 - 잘리지만 않으면 됨)
2. 홈 화면에 추가한 웹앱에서 위쪽 상태 표시줄·아래 홈 막대와 내용이 겹치지 않는지(M-2 판단 근거)
3. 이메일·비밀번호 입력창을 눌러 키보드가 올라왔을 때 입력창이 가려지지 않는지
4. 작은 안드로이드(폭 360 미만)를 쓸 수 있다면 로그인 유지·찾기 줄(M-1)
