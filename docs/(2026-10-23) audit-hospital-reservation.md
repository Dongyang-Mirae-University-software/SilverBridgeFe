## A. 보안·인가 - PASS (IDOR PASS)
gosky 실서버(`127.0.0.1:6510/api/reservation/...`, 로그인 없이 - 허용 목록이 로그인보다 먼저):

| 시도 | 결과 |
|---|---|
| `admin/users`·`auth/api-keys`·`users/me` | 404 |
| `hospitals/%2e%2e/admin/users`·`hospitals/..%2Fadmin`·`reservations/my/..%2F..%2Fadmin` | 404 |
| `HOSPITALS`·`hospitals/1%2Favailable-slots`·`date=...%0a` | 404 |
| `reservations/%31%32/cancel`(GET) | 404 |
| HEAD | 404 / OPTIONS 204(Next 기본, 중계 없음) / DELETE·PUT 405 |
| `hospitals/`·`hospitals//` | 308(Next 정규화) |
| `date=2026-10-24&date=../x` | 첫 값만 검증 후 다시 조립(401 단계까지 감) |

머지 직후 테스트 보호자 계정(gosky): 로그인 200 / `admin/users` 404 / 헤더 없는 예약 POST 403 / 연결 안 된 wardId 403 / 예약 201(id 251) → 피보호자 계정 목록 `BOOKED` → 취소 200 → `CANCELED`.

- 502는 고정 문구 "예약 서비스에 연결하지 못했습니다.", 로그는 `[RESERVATION-PROXY] <고정 코드>`만(테스트로 원문·토큰 미포함 고정).
- 증상(건강 정보): 화면에 입력·표시 없음, localStorage·sessionStorage·console 사용 없음. 단 BFF는 본문을 거르지 않는다(L-1).

## B. 기능 정합성
- KST: `Intl`(Asia/Seoul)로 오늘·지금, `Date.UTC`로 일수·요일 - 자정 경계 맞음(단위 테스트 UTC 15:05 → KST 다음 날).
- 시간 칸: 예약 서비스 `generateHalfHourSlots`와 같은 규칙, 빈 시간에 없으면 마감, 오늘 지난 시각 마감.
- 다가오는/지난: 예약됨·확정이고 시각이 안 지난 것만 다가오는 진료, 나머지(지난 예약·완료·취소)는 지난 진료.
- 피보호자 화면 버튼 0개(브라우저 테스트 고정).

## 이슈
🔴 0 · 🟠 0 · 🟡 5 · 🟢 6. "기존"은 PR #102 전부터 있던 동작이다.

### 🟡 M-1 BE 일시 오류가 401(강제 로그아웃)·거짓 403이 된다 (기존, `route.ts` `fetchSb`)
`fetchSb`는 응답이 ok가 아니면 모두 null이다. `/api/user/me`가 5xx·429면 BFF가 401 "로그인이 필요해요"를 내고, `apiClient`가 refresh 실패 시 세션을 지운다. 연결 목록 조회가 5xx면 "연결된 피보호자가 아니에요" 403(거짓). 독립 리뷰는 🟠으로 봤으나 기존 동작이고 BE 장애 + refresh 실패가 겹쳐야 해 🟡로 둔다.
수정안: 401·403만 null, 그 밖은 throw → 기존 catch로 502(`PROFILE_LOOKUP_FAILED`·`WARD_LOOKUP_FAILED`), `NEXT_PUBLIC_API_DOMAIN` 없음은 503. 테스트 추가.

### 🟡 M-2 새 예약 계정 동시 생성 경합 → 첫 방문 502 (이번 PR로 드러남, `route.ts` `getReservationToken`)
피보호자 화면이 `reservations/my`·`hospitals`를 동시에 부르고 둘 다 본인 계정을 쓴다. 계정이 없으면 둘 다 login 401 → signup, 예약 서비스가 중복 이메일에 409(`auth.service.ts`)를 줘 한쪽이 `ACCOUNT_FAILED` 502. 예전 피보호자 화면은 요청이 하나였다. 결과: 처음 여는 피보호자는 오류 카드 또는 주소 누락(다시 불러오면 정상).
수정안: `profile.id`별 진행 중 Promise 공유 + signup 409면 login 한 번 더.

### 🟡 M-3 예약 중 [예약 취소]·[이전]을 눌러도 성공하면 완료 화면으로 점프 (이번 PR, `GuardianHospitalContent.tsx`)
"예약하는 중"에도 머리줄 [예약 취소]·[이전]이 눌린다. 서버가 예약에 성공하면 `onSuccess`가 `setStep('done')` - 이미 목록으로 돌아간 뒤라 병원 이름이 빈 채(" · 안과") 완료 화면이 뜬다. 예약은 실제로 잡혔으니 결과는 맞지만 사용자는 취소했다고 믿을 수 있다.
수정안: pending 중 두 버튼 비활성화, 병원 이름은 `mutate` 변수에 담기.

### 🟡 M-4 지금 접수를 받지 않는 병원이 목록에 나오고 확인 단계에서야 거절 (이번 PR)
예약 서비스는 **현재** `operationStatus=OPEN && acceptingPatients`가 아니면 `HOSPITAL_CLOSED` 400("현재 예약 가능한 상태가 아닙니다.")이다. 새 목록은 `bookingAvailable`만 거르고 상태를 보이지 않아(디자인이 뺌) 3단계를 다 거친 뒤 거절된다. 예전 화면은 "진료 중·휴진" 등을 표시했다. 목록 `staleTime` 60초로 상태가 낡을 수도 있다.
수정안: 목록에서 OPEN이 아닌 병원은 "지금은 예약을 받지 않아요"로 흐리게(누를 수 없게), 또는 확인 단계 진입 시 병원 상태 재조회. 문구·표시는 디자인 결정이 필요.

### 🟡 M-5 BFF의 외부 호출에 시간 제한이 없다 (기존, `route.ts` 모든 `fetch`)
BE·예약 서비스가 멈추면 Next 요청이 매달린다. 수정안: `AbortSignal.timeout(10_000)`, 실패는 기존 502 경로.

### 🟢 L-1 요청 본문을 거르지 않고 크기 상한이 없다 (기존)
POST 본문을 그대로 넘겨 `symptomSummary`·`memo`·`emergencyFlag` 등을 직접 호출로 쓸 수 있다. 보호자는 이미 그 피보호자 대리 권한이 있어 권한 우회는 아니다. 수정안: 화면이 쓰는 9개 필드만 다시 조립, 4KB 상한.

### 🟢 L-2 예약 토큰 만료·비밀값 교체 시 재시도 없음, 캐시 상한 없음 (기존)
예약 서비스 401 → 502로 한 번 실패한다(다음 요청은 재발급). 수정안: 401이면 캐시 삭제 후 1회 재시도, `tokenCache` 항목 정리.

### 🟢 L-3 예약 서비스 5xx·400 문구가 그대로 화면에 간다 (일부 이번 PR)
업스트림 502·503이 그대로 전달돼 화면이 "예약 서비스를 쓸 수 없어요(503)"로 안내할 수 있다. 400의 class-validator 영어 문구도 노출 가능(화면은 항상 올바른 값을 보내 실제로는 드묾). 수정안: 업스트림 5xx는 502 고정 문구, 400은 알려진 `code`만 서버 문구.

### 🟢 L-4 허용 목록 경계 (이번 PR, `reservationRoutes.ts`)
id 10자리를 허용해 int32를 넘는 값(`9999999999`)이 예약 서비스에서 500이 될 수 있고, `2026-99-99` 같은 없는 날짜도 통과한다. 권한 문제는 아니다. 수정안: id 9자리, 날짜 `Date.UTC` 왕복 검사.

### 🟢 L-5 접근성 (이번 PR)
- 번호가 틀려 [예약하기]가 비활성일 때 이유 안내 없음(`aria-invalid`만).
- 행마다 "이 예약 취소"·"같은 곳 다시 예약" 이름이 같아 스크린리더로 구분 안 됨(날짜·병원을 이름에).
- 취소 확인으로 바뀔 때 포커스가 사라진다 / 페이지 숫자 버튼에 "N페이지" 이름 없음 / 날짜 칸에 "오늘" 표시 없음.

### 🟢 L-6 화면을 오래 열어 두면 '오늘·지금'이 갱신되지 않는다 (이번 PR)
`kstToday`·`kstNowTime`을 그릴 때만 계산해 자정·시각을 넘기면 지난 시각이 고를 수 있게 남는다. 예약 서비스도 오늘의 지난 시각은 막지 않는다. 수정안: 확인 단계 진입·제출 직전 재검사(또는 1분 tick).

### 채택하지 않은 지적
- `.select`의 `min-width:160px` 375px 넘침 - 그 값은 줄바꿈되는 `.rowName`에 있다(브라우저 테스트로 넘침 없음 확인).
