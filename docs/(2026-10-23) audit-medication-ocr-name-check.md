## B. 기능 정합성 - PASS
| 전달 내용 | 확인 |
|---|---|
| 노란 칸 = `low \|\| inList === false` | `needsNameCheck` 한 곳, 이름 칸과 확인 박스가 같이 씀 |
| `inList === null`·칸 없음은 경고 안 함 | `drug.inList === false`일 때만 `notInList` |

| 직접 고치면 강조·안내·칩 해제, 재대조 없음 | 입력 `onChange`도 `renameDrug` |
| "다시 찍기" | 성공 시 새 결과로 초안을 통째로 바꾸고, 실패 시 고쳐 둔 초안을 그대로 둔다(기존 동작, 강조 상태도 그대로) |
| 탭 전환 | 빈 약 1개로 초기화 - 남는 강조 없음 |

|---|---|---|
| 모달 가로 넘침(scrollWidth/clientWidth) | 335/335 | 480/480 |

| 칩 높이 | 26px | 26px |

## D. 테스트 - PASS
단위 +4(inList 값별 변환·제안 정리·`needsNameCheck`·`renameDrug`), 브라우저 +3(제안 3개 칩·0개 문구만·직접 수정·null/옛 응답 무경고·true+low 노란 칸·칩 미선택 시 원래 이름 등록·375px 넘침 없음). 전달된 6가지 경우를 모두 덮는다.
- 빈 곳(작음): "다시 찍기" 성공 시 이전 결과의 안내·칩이 새 결과로 바뀌는지는 별도 테스트가 없다. 초안을 통째로 바꾸는 기존 경로라 위험은 낮다.

## 이슈
Critical·High·Medium 없음.

### 🟢 L-1 칩 테두리 대비 2.79:1 (WCAG 1.4.11 기준 3:1 미달) - ✅ 수정 완료
칩 테두리가 `--sb-sun`(#c99030)이라 흰 배경에서 2.79:1이다. 칩 안 글씨(18.8:1)로 버튼임은 알 수 있어 막히지는 않는다. 기존 노란 칸 테두리도 같은 토큰이다.
- 제안(선택): 칩 테두리만 `--sb-warn`(#a3602c, 4.92:1)로. 노란 칸 테두리는 배경색이 함께 있어 그대로 둬도 된다.

### 🟢 L-2 칩이 "누르면 바뀐다"는 단서가 문구에 없음 - ✅ 수정 완료
안내 문구는 "봉투와 다시 확인해 주세요"뿐이라, 칩이 바꾸기 버튼인지 참고 목록인지 화면만으로는 덜 분명하다(스크린리더는 레이블로 안다).
- 제안(선택): 칩 앞에 "비슷한 이름:" 같은 짧은 머리말. 전달 문구를 바꾸는 일이라 결정 사항이다.

### 🟢 L-3 칩 터치 영역 26px - ✅ 32px로 상향
WCAG 2.5.8(최소 24px)은 충족, 2.5.5(44px)는 미달. 전달 내용이 "작은 버튼·행 높이가 크게 늘지 않게"라 의도대로다. 보호자가 잘못 누르면 이름 칸을 다시 고치면 된다.

### ℹ️ 참고
- 공백만 넣었다 지워도 그 행의 강조가 사라진다 - 전달 3번("직접 고치면 끈다, 다시 대조하지 않음") 그대로라 수용.
- 칩 클릭 시 `suggestion.slice(0, 100)`은 정리 단계에서 이미 100자 초과를 빼므로 실효가 없는 방어 코드다. 해는 없다.
